# Архитектура Ритма

## Разделение ответственности

Приложение состоит из нативной оболочки, локального HTTP-сервера, двух workflow n8n и Python-модулей интеграций. Swift запускает интерфейс и открывает внешние ссылки в браузере. Python обслуживает чат и историю, сериализует запросы к тяжёлым сервисам и управляет расписанием. n8n собирает календарный контекст и вызывает локальную модель.

Такое разделение оставляет обработку аккаунтов и жизненный цикл процессов в обычном проверяемом коде, а календарный workflow — визуально доступным для настройки.

## Жизненный цикл запроса

1. UI сохраняет пользовательское сообщение и создаёт ожидающий ответ в SQLite.
2. Рабочий поток получает общий файловый lock. Расписание использует тот же lock: два процесса не запускают конкурирующие генерации.
3. Lifecycle-контекст поднимает Ollama, Docker Desktop и n8n, дожидается готовности.
4. В workflow передаются запрос, ограниченная история и отобранные задачи Strive. Календарь читается через CalDAV.
5. Для запросов о плане или почте Gmail читается отдельно; каждое письмо получает короткую выжимку от локальной модели.
6. Ответ с почтовым разделом сохраняется локально. Только затем фиксируется обработанный период Gmail.
7. В блоке очистки модель выгружается, сервисы останавливаются с учётом других контейнеров, моделей и выполнений.
8. UI снимает состояние ожидания после завершения обработки.

Контекст `engine()` обеспечивает очистку и при исключении. После прерванной работы отдельная проверка может завершить оставшиеся сервисы, если lock свободен.

## Расписание и сон

LaunchAgent не держит Python-процесс постоянно: запускает короткую проверку каждые пять минут и при входе. Временная зона явно задана как Europe/Moscow. Функция `due_slot` выбирает один последний актуальный слот: сегодня 07:00, сегодня 23:00 либо вчера 23:00 до наступления утра.

Состояние содержит завершённый слот и время попытки. Повторные ошибки ограничены паузой 15 минут. Успешные выполнения workflow дополнительно проверяются в базе n8n, чтобы не повторять уже созданный план. Mac не пробуждается из сна.

## Gmail: отчёт без потери периода

Подключение использует TLS IMAP, `select(..., readonly=True)` и `BODY.PEEK`. Флаги писем не изменяются. Список ограничивается значением UIDNEXT, полученным в начале чтения: новые поступления во время обработки остаются для следующего отчёта.

Контрольная точка содержит UID, UIDVALIDITY и время отчёта. При первой настройке или смене UIDVALIDITY используется дата поступления INTERNALDATE, а не ненадёжная дата из заголовка отправителя. После успешной обработки UID позволяет не перечитывать весь ящик.

За отчёт обрабатываются до 40 писем от старых к новым. При достижении лимита контрольная точка остаётся на последнем обработанном UID. Ошибка подключения или хотя бы одной выжимки не продвигает период этой почты. Повтор отдельных писем допустим; незаметный пропуск писем недопустим.

Для автоматических планов почтовый раздел хранится отдельно по идентификатору выполнения n8n и добавляется при восстановлении локального кэша планов. Для чата итог сохраняется в SQLite. Проверка пароля не потребляет письма.

## Strive: предметная фильтрация

Интеграция обращается только к разрешённым read-only маршрутам. Из проектов отбираются незавершённые задачи текущего пользователя и задачи без исполнителя; архивные исключаются. Столбец должен состоять из числа или диапазона чисел — дней текущего месяца. Срок задачи и дата столбца остаются разными полями.

Число задач и длина контекста ограничены. При ошибке API можно использовать явно помеченную копию не старше суток и только из текущего месяца.

## Хранение

| Данные | Место |
| --- | --- |
| Чаты и ответы | `runtime/chat.sqlite` |
| Кэш планов | `runtime/plans-cache.json` |
| Состояние расписания | `runtime/wake-state.json` |
| Состояние Gmail | `runtime/mail-state.json` |
| Почтовые разделы планов | `runtime/mail-reports.json` |
| Токен Strive, пароль Gmail | macOS Keychain через Swift Security framework |
| CalDAV credentials | Собственный том n8n |

Файлы runtime создаются с приватными правами. Они не входят в репозиторий. Публикуемые JSON workflow являются шаблонами без credentials, личных календарных URL и сохранённых выполнений.
